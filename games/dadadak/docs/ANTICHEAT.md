# 안티치트 / 안티매크로 전략

> 전제: 완벽한 차단은 불가능하다(하드웨어 매크로는 원리적으로 사람과 구분 한계).
> 목표는 **랭킹의 신뢰**다 — 치터를 전부 잡는 게 아니라, 잡히지 않은 치터가 랭킹을 오염시키지 못하게 한다.
> 모든 임계값은 [가정]이며 운영 데이터(flagged 비율, 어드민 리뷰)로 재보정한다.

## 위협 모델

| 공격 | 예시 | 방어선 |
|------|------|--------|
| A. 브라우저 내 스크립트 | 콘솔에서 `dispatchEvent` 연사, 북마클릿 | **1차: isTrusted** |
| B. 소켓 직접 위조 | 클라이언트 우회, `battle:tick` 대량 전송 | **2차: 서버 절삭·상한** |
| C. OS 오토클리커 | 오토클릭 앱, 매크로 키보드(신뢰된 이벤트 발생) | **3차: 통계 탐지** |
| D. 하드웨어 매크로 | 아두이노 HID, 연사 마우스 | 3차 + 물리 한계 상한 |

## 방어 레이어 (구현됨)

### 1차 — 클라이언트: 합성 이벤트 차단
- 모든 입력 핸들러(`TapArea`, 홈 히어로)에서 `event.isTrusted === false` 무시.
- 페이지 컨텍스트의 JS로는 isTrusted를 위조할 수 없다 → 공격 A 원천 차단.
- 클라이언트 방어는 우회 가능하므로 참고 방어선일 뿐, 판정 근거는 아니다.

### 2차 — 서버: 하드 상한 (판정의 기준선)
- 배틀: 250ms 윈도우당 8클릭 절삭 → 이론상 최대 32CPS (PRD F7).
- 배틀: 경기 평균 CPS > 20 → `flagged=1`, 랭킹·최고기록·누적 제외.
- 무한 딸깍: 요청당 120클릭 + 사용자당 분당 12회(≈24CPS) + **일일 50,000 적립 상한**
  → 매크로를 돌려도 등급 인플레 속도가 제한됨 (무접점 5M까지 최소 100일).
- 클라이언트가 보낸 총합은 절대 신뢰하지 않는다 — 서버 확정값만 저장.

### 3차 — 서버: 통계 탐지 (기계 티 나는 균일함)
- 사람의 연타는 윈도우별 클릭 수가 출렁이고, 오토클리커는 간격이 일정하다.
- 배틀 종료 시 윈도우 분포의 **변동계수(CV = std/mean)** 를 검사:
  평균 ≥ 2클릭/윈도우(8CPS)이면서 CV < 0.15 → `flagged=1`.
- 저속(8CPS 미만)은 검사하지 않음 — 오탐 방지 우선.
- 한계: "일부러 불규칙하게 흔드는" 고급 매크로는 통과 가능 → 4차로 보완.

## 4차 — 로드맵 (설계만)

| 아이디어 | 내용 | 효과 |
|----------|------|------|
| 골든 윈도우 반응 검사 | 배틀 중 서버가 무작위 시점에 색 변화를 방송, 반응 지연 분포 분석. 사람 ~150-300ms, 매크로는 반응 없음/즉답 | 공격 C·D에 강함 |
| 세션 프로파일 | 같은 유저의 CPS 분포가 갑자기 계단식 상승하면 리뷰 큐 | 계정 단위 탐지 |
| 어드민 리뷰 큐 | flagged 경계 사례(CV 0.15~0.2 등)를 `/admin`에 목록화, 수동 확정 | 임계값 보정 데이터 확보 |
| 좌표 분산 신호 | 터치 좌표 분산이 0에 가까우면 의심 신호(참고용, 위조 가능) | 보조 신호 |
| 일일 미션·등급의 배틀 연동 | 등급 상승 요건에 "정상 배틀 N판" 포함 → 탭 농사만으로는 등급 못 올림 | 인센티브 구조로 방어 |

## 운영 원칙

- flagged는 **차단이 아니라 격리**: 결과는 보여주되 랭킹·기록·누적에서 제외 (오탐이 사용자 경험을 죽이지 않게).
- flagged 비율은 daily_stats로 어드민에서 상시 관찰 — 급등하면 임계값 점검.
- 논쟁 소지가 있는 강한 조치(계정 제재 등)는 Phase 1 범위 밖.
